<p align="center">
TrueFPS keeps FFXI running at normal speed at custom frame rates, with automatic recovery for cutscene movement stalls caused by high FPS. Keep smooth mode enabled for this protection, and choose optional cutscene speeds up to 6×.
</p>

## ![Install](https://readme-typing-svg.demolab.com/?font=Cinzel&size=25&duration=1&pause=0&color=638EBD&center=false&vCenter=true&repeat=false&width=600&height=42&lines=Install&letterSpacing=0.5px&weight=700)

Developed with **Ashita v4.3.2.1**, plugin interface **4.30**.

1. [Download latest release of TrueFPS](https://github.com/SQLCommit/TrueFPS/releases/latest). Choose the plugin ZIP whose `Interface-N.NN` matches your Ashita plugin interface.
2. Extract into `/ashita/`. The plugin should be at `/ashita/plugins/truefps.dll`.
3. In game, run `/load truefps`.

**Load automatically:** Add `/load truefps` to your startup script in `/ashita/scripts/`.

**Defaults:** Smooth mode on, frame limit **Max** (monitor refresh), FPS counter on, and cutscenes at normal speed. Open `/truefps` to change them.

## ![Features](https://readme-typing-svg.demolab.com/?font=Cinzel&size=25&duration=1&pause=0&color=638EBD&center=false&vCenter=true&repeat=false&width=600&height=42&lines=Features&letterSpacing=0.5px&weight=700)

<details open>
<summary><strong>Cutscenes</strong> — Automatic recovery from high-FPS movement stalls, pausing on menus, plus optional speeds up to 6×.</summary>

<dl>
<dd>

When high FPS leaves a cutscene actor stuck short of its destination, **smooth mode** detects the stall and increases its movement step to help it continue. Recovery starts after about half a second, so a brief pause can still occur.
Normal speed is the default. You can exclude targets or pause acceleration during selected menus. Acceleration ends when the cutscene finishes or you zone.

**Note:** All the freezes we know about are handled at any speed. If you find one that is not, please report it.

</dd>
</dl>

</details>

---

<details>
<summary><strong>Frame limit</strong> — Choose 30, 60, monitor refresh, a custom rate, or uncapped.</summary>

<dl>
<dd>

**Max** picks up changes to your display's refresh rate automatically.

</dd>
</dl>

</details>

---

<details>
<summary><strong>Smooth mode</strong> — Keep normal game speed at custom frame rates, with smoother motion.</summary>

<dl>
<dd>

Turning it off can change game speed at custom rates. Some animations still use native timing even with it enabled.

**Works with xicamera:** Load either one first. TrueFPS leaves the camera distance constant xicamera edits untouched, and keeps xicamera's camera jitter removal instead of re-timing it; the rest of the camera stays smooth. A camera rate another tool retunes in the game's own data is followed about once a second, including where TrueFPS has replaced the instruction that read it: TrueFPS keeps its own copy of that rate on the new value, so the retune still takes effect.

</dd>
</dl>

</details>

---

<details>
<summary><strong>Background limit</strong> — Use a lower FPS cap when the FFXI window is not in focus.</summary>

<dl>
<dd>

**Off** keeps your normal rate; **Uncapped** removes the cap. Your normal setting returns when the FFXI window regains focus.

</dd>
</dl>

</details>

---

<details>
<summary><strong>FPS counter</strong> — Move or lock the counter, show the longest frame, and choose colours that change with your FPS.</summary>

<dl>
<dd>

**Colour threshold** uses three configurable colours, separated by thresholds of 30 and 60 FPS by default.

</dd>
</dl>

</details>

---

<details>
<summary><strong>Frame diagnostics</strong> — Inspect frame-time breakdowns and export retained frames to CSV.</summary>

<dl>
<dd>

Breakdowns separate game logic, rendering, addons and plugins, GPU and driver time, and TrueFPS's own processing and limiter time.

</dd>
</dl>

</details>

---

<details>
<summary><strong>Zoning waits</strong> — Keep high frame rates from shortening connection and shutdown waits when the relevant routines are available.</summary>

<dl>
<dd>

**Zone wait** shows a wait in progress and keeps the last one visible for 30 seconds afterward. It shows `n/a` when the protection is unavailable.

</dd>
</dl>

</details>

**After a client update, check Routines Tab for unavailable features. The FPS counter, Frames tab, and captures still work if the game build is unrecognised.**

**Compatibility:** Retail: every routine. HorizonXI: every routine but the hold bar, which that client does not have; the
Routines tab shows it dim as not in this client. On a retail client, which has the hold-time window, a hold bar whose code is not found
is reported as a failure, not as absent.

## ![Commands](https://readme-typing-svg.demolab.com/?font=Cinzel&size=25&duration=1&pause=0&color=638EBD&center=false&vCenter=true&repeat=false&width=600&height=42&lines=Commands&letterSpacing=0.5px&weight=700)

| Command | Action |
| :--- | :--- |
| `/truefps` | Show or hide settings |
| `/truefps ui` | Show or hide settings |
| `/truefps status` | Print current status |
| `/truefps limit <rate>` | Use `30`, `60`, `max`, `off` (uncapped), or a custom number |
| `/truefps smooth on` / `off` | Enable or disable smooth mode |
| `/truefps background <rate>` | Use a number, `max`, `uncapped`, or `off` (keep normal rate) |
| `/truefps cutscene <speed>` | Use `off` or a multiplier from `2` through `6` |
| `/truefps overlay on` / `off` | Show or hide the FPS counter |
| `/truefps overlay lock on` / `off` | Lock or unlock counter dragging |
| `/truefps overlay detail on` / `off` | Show or hide the longest-frame readout |
| `/truefps overlay bands on` / `off` | Enable or disable FPS-based counter colours |
| `/truefps frames` | Summarize the last 10 seconds |
| `/truefps frames save` | Export all retained frames to CSV |
| `/truefps diag` | Write a diagnostic report to the log |
| `/truefps help` | Show command help |

For settings commands, omit the value to see the current setting and usage. `/truefps overlay` reports all four counter switches. To reapply a frame limit, include its value, such as `/truefps limit 60`.

`/tf` also works as the prefix. `fps` and `rate` alias `limit`; `bg` aliases `background`; `cs` aliases `cutscene`. Rate commands accept 5–1,000 FPS; both custom-rate sliders stop at monitor refresh rounded up. `uncapped` also works for `limit off`, and `unlimited` for `background uncapped`.

## ![Export and saved data](https://readme-typing-svg.demolab.com/?font=Cinzel&size=25&duration=1&pause=0&color=638EBD&center=false&vCenter=true&repeat=false&width=600&height=42&lines=Export+and+saved+data&letterSpacing=0.5px&weight=700)

**Frame exports**

- Use `/truefps frames save` for all retained frames, not just the ten-second summary. Times are in milliseconds; unmeasured values are blank.
- **Files:** `/ashita/logs/truefps/<Name>_<id>/frames_<date>-<time>.csv`

**Settings and logs**

- **Settings:** `/ashita/config/truefps/<Name>_<id>/truefps.ini`
- **Log:** `/ashita/logs/truefps/<Name>_<id>/truefps.log`
- Before login, settings use `/ashita/config/truefps/truefps.ini`; logs and captures use `/ashita/logs/truefps/`. New character settings start from built-in defaults.
- **Backup:** Copy `/ashita/config/truefps/` for settings and `/ashita/logs/truefps/` for captures. Run `/truefps diag` before sharing a log with a bug report.

For source builds, see [Build instructions](BUILD.md).
